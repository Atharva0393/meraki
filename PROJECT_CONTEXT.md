## 2. Design direction (the brief, condensed)

The site must read as: **premium, architectural, editorial, calm,
sophisticated, minimal, intentional, cinematic, expensive without being
flashy.** Reference point: *Apple product-page restraint × high-end UK
architecture studio × editorial print design.*

Explicitly **not**: SaaS, generic agency template, AI-generated-looking,
overly animated portfolio, startup landing page, Webflow template,
glassmorphism, neon, futuristic/AI aesthetics.

Governing principle: **less, but better.**

**Visual system:**
- Background: warm ivory (`--color-ivory: #f6f1ea`)
- Secondary surface: stone (`--color-stone: #ede6da`) — used for the hero's
  outer backdrop band and image placeholders
- Primary text: near-black charcoal (`--color-charcoal: #211f1c`,
  `--color-ink: #1c1a17`)
- Accent: muted terracotta/copper clay (`--color-clay: #a9673f`) — used
  sparingly (CTA fills, active nav underline, small accent rules), never as
  a dominant fill
- Secondary text: warm grey (`--color-warm-grey: #6b655c`)
- Dividers: hairline (`--color-hairline: #ded5c4`)
- Type: **Fraunces** (editorial serif, headlines) + **Inter** (sans, body/UI),
  loaded via `next/font/google` in `src/app/layout.tsx`
- Generous whitespace, thin borders/dividers, pill-shaped buttons and tags.
  Rounded corners used selectively (buttons, tags, the hero's own card
  frame) — the site should still read as editorial, not card-based.
- Explicitly avoid: heavy shadows, SaaS card grids, gradients, glassmorphism,
  decorative/unnecessary icons, fake stats/testimonials/client logos.

All tokens live in `src/app/globals.css` (`:root` + Tailwind v4 `@theme
inline` block) and are documented in
`design-system/meraki-designs/MASTER.md`.

## 6. The hero image — history, don't regress

File: `public/images/hero/hero-home.webp` (referenced via
`src/lib/media.ts`). Original source: `bgimage.png` in the project root
(6144×4096, untouched, kept as raw source).

What happened, in order — useful if the image ever needs reprocessing:
1. Original PNG had ~25% of empty sky above the roofline and generous
   side margins.
2. Cropped tightly to the actual visible building bounds (roughly
   `left,top,right,bottom = 1067,1251,5169,4096` in the original's pixel
   space) so the building fills nearly its whole frame.
3. Background-removed via a color-distance alpha mask (Python/Pillow,
   sampling the corner background color, thresholding by distance) to get
   a genuine transparent cutout — not just a matching flat color — so the
   asset can sit directly on the ivory page/card background with no visible
   "card" seam, and so headline text can overlap the roofline without a
   rectangular box being visible.
4. Background tone color-corrected to match the `--color-ivory` token
   exactly (small RGB shift).
5. Final asset: 2800×1942 WebP with alpha, ~1MB.

**Why the hero image uses a CSS `scale-150` transform instead of a bigger
container:** the user explicitly required the *visible size* of the
building to increase without changing the container's layout box (which
would shift the CTA row position / hero height). `transform: scale()` (in
Tailwind v4, compiled to the standalone CSS `scale` property, not
`transform`) changes only painted pixels, not layout — exactly what was
needed. **Do not "fix" this by just enlarging the image div** — that was
tried and explicitly rejected by the user for changing spacing elsewhere.

## 7. Motion system (built and verified this session — not upcoming work)

**Important correction vs. any older notes:** the "visual polish + motion"
phase described below is **already implemented, tested, and passing
lint/typecheck/build** — it is not a future task. If resuming from an older
summary that says "Motion: NEXT PHASE," that summary is stale.

Core primitive: `src/components/reveal.tsx` — `"use client"` component,
IntersectionObserver-based (fires once, `threshold: 0.15`), toggles an
`is-visible` class that a CSS transition picks up. Two variants:
`variant="up"` (fade + translateY, default) and `variant="scale"`
(fade + scale, used for images). Delays via `delayMs` prop
(`style={{transitionDelay}}`) for staggering.

CSS in `src/app/globals.css`:
- `.animate-fade-up`, `.animate-reveal-image` — original **load-triggered**
  keyframe animations, still used by the hero only (already had motion
  before this phase; left alone).
- `.animate-page-fade` — **opacity-only** load animation used by
  `PageTransition` for route changes. **Important:** this used to include a
  `transform: translateY()` — that was a real bug (see below) and was
  removed. Do not re-add a transform here.
- `.reveal` / `.reveal-scale` (+ `.is-visible`) — the scroll-triggered
  transition-based classes `Reveal` toggles.
- Everything respects `prefers-reduced-motion: reduce` (one consolidated
  media query at the bottom of the file disables all animation/transition
  classes and snaps to end-state).

Where motion was added:
- `src/components/page-transition.tsx` — wraps `{children}` in
  `src/app/layout.tsx`, keyed by `usePathname()`, so every route change
  re-mounts and re-fades content in (~400ms, opacity only).
- `src/components/site-header.tsx` — sticky (`sticky top-0`) on the four
  interior pages, with a scroll listener toggling a blurred/hairline-bordered
  background once `scrollY > 8`. **Homepage hero's own nav is intentionally
  NOT sticky** — making it sticky would break the approved rounded-card
  composition (nav would visually detach from the card once stuck), so this
  was a deliberate scope decision, not an oversight.
- `src/components/navbar.tsx` — real full-screen mobile menu (slide/fade
  overlay, header row incl. close button stays visible above it via
  `z-40`), animated underline on desktop nav links, active-page indicator.
- `src/components/pill-button.tsx`, `arrow-link.tsx` — hover/press
  micro-interactions (subtle lift + scale on press; grow-in underline on
  links).
- `src/components/numbered-list.tsx` (shared by Studio principles and
  Services list), `project-gallery.tsx`, `project-visual.tsx`,
  `selected-projects.tsx`, `studio-intro.tsx`, `page-hero.tsx`,
  `closing-cta.tsx`, `contact-form.tsx` — all wrapped with `Reveal` and/or
  given hover-state refinements (numeral color shift, title translate,
  link opacity).

### Two real bugs found and fixed this session (worth knowing about)
1. **Fixed-position elements broke sitewide.** `animate-page-fade`
   originally used `transform: translateY()`. Any element with a non-`none`
   transform becomes a CSS containing block for `position: fixed`
   descendants. Since `PageTransition` wraps the entire page, this silently
   broke the mobile nav overlay (and would break any other `fixed` element)
   everywhere. Fixed by making that animation opacity-only. **If you ever
   add a transform-based animation to a wrapper high in the tree, check
   this doesn't happen again.**
2. **Duplicate DOM IDs.** `Navbar` is rendered *twice* by `hero.tsx`
   (desktop variant + mobile variant, toggled via Tailwind breakpoints —
   this predates the motion work and wasn't changed). Once `Navbar` gained
   a mobile-menu overlay with a static `id="mobile-nav"`, having two
   instances meant duplicate IDs and `aria-controls` pointing at the wrong
   (hidden) instance. Fixed with `useId()` for a collision-free ID per
   instance. If you ever add more stateful IDs to `Navbar`, remember it can
   mount more than once per page.

### Known testing-environment limitation (not an app bug)
The `:focus` pseudo-class could not be reliably triggered via this
session's browser-automation tooling (`element.focus()` updates
`document.activeElement` but doesn't always trigger real CSS `:focus`
matching in that environment; real click-to-focus was also unreliable
there). The contact form's focus-underline CSS was verified correct by
reading the compiled Tailwind output directly (correct selector, correct
specificity) rather than by a live screenshot. If a fresh session has a
working browser tool, it's worth a quick real visual check, but there's no
reason to suspect the CSS itself is wrong.

## 9. Project philosophy / working rules

The user has repeatedly emphasized: **don't overcomplicate this, fewer
prompts, clean and premium execution over technical completeness.**

1. Read this file before changing anything.
2. Inspect current implementation before modifying it (read the actual
   component, don't assume from memory).
3. Preserve approved decisions (hero composition, image treatment, palette)
   unless the user explicitly asks to revisit them.
4. Don't rebuild working pages without a clear reason.
5. Never invent business info, contact details, or project photography —
   use the established placeholder patterns instead.
6. Keep the visual system consistent site-wide (reuse `Eyebrow`,
   `ArrowLink`, `PillButton`, `PageHero`, `NumberedList`, `Reveal` rather
   than inventing new one-off patterns).
7. Motion stays subtle/premium: opacity + transform only, ~500–900ms major
   reveals, ~200–400ms micro-interactions, no bounce, no parallax, respect
   `prefers-reduced-motion`.
8. Don't add dependencies unless genuinely necessary — this project has
   deliberately stayed on zero UI/animation libraries.
9. Before calling UI work done: actually load it in the browser (desktop +
   mobile), not just code review. Run `npm run lint`, `npx tsc --noEmit`,
   `npm run build` and confirm all pass, and check for browser console
   errors.
10. Prefer fewer, larger, meaningful changes over many small ones.
